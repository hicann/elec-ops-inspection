# 示例可复现性检查清单

读取时机：新增或审查 `elec-ops-inspection` 算子示例、README 调用片段、PR 验证说明时读取。

## 1. 运行入口

- 示例文件路径明确，例如 `unique_v3/examples/test_unique.py`。
- 从仓库根目录运行时命令可复制。
- 构建命令、安装命令、运行命令分开写。
- 如果需要先安装算子包，说明包名或安装产物位置。
- 不依赖个人目录、IDE 配置、临时缓存或未提交脚本。

## 2. 环境要求

- 明确 CANN、Python、PyTorch、torch_npu、torchaudio 或 pybind 依赖。
- 明确是否必须有 NPU。
- 无 NPU 环境下至少能做静态检查、CPU reference 检查或 dry-run 说明。
- 环境变量必须列出用途，例如 `ASCEND_HOME_PATH`、`LD_LIBRARY_PATH`。
- 不把本地环境默认值写成仓库通用事实。

## 3. 输入数据

- 优先使用脚本内合成数据。
- 固定随机种子，确保输出稳定。
- 输入 shape、dtype、layout 和属性开关必须写清。
- 对电力巡检场景的映射只解释规模和类型，不声称真实现场数据。
- 私有数据、生产截图、现场音频或点云不能作为默认示例依赖。

## 4. 输出与参考检查

- 输出包含可判定字段，例如 shape、dtype、loss、unique count、inverse/counts 一致性。
- 若有 CPU reference，给出同输入对照。
- 精确算法使用 `torch.equal` 或逐元素一致检查。
- 近似算法写明误差指标和阈值。
- 示例失败时应输出清晰错误，而不是只打印底层堆栈。

## 5. 文档表达

- README 片段与实际脚本参数一致。
- PR 描述写出运行过的命令和结果。
- 未运行的 NPU-only 步骤写明原因和需要 reviewer 复核的命令。
- 示例只证明“调用路径可运行”，不能替代性能 benchmark 或端到端系统验收。

## 6. 阻塞条件

- 示例必须依赖未公开数据且没有合成替代。
- 示例命令无法从仓库根目录定位到文件。
- README 中的接口名、参数名或输出数量与代码不一致。
- 缺少任何可判定输出，reviewer 无法知道运行是否正确。
