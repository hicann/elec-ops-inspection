# optimized_transducer 使用说明

## 前置条件

本仓库提供 `optimized_transducer` 的 Host、Kernel、ACLNN 示例和 pybind 源码，但不包含旧版文档引用的 `build.sh --pkg`、`build.sh --run_example` 等仓库外构建入口。

使用 pybind 模块前，需要先通过实际采用的 CANN 算子工程构建并安装算子包。当前 pybind 构建配置默认从 `custom_nn` vendor 目录查找 ACLNN 头文件和动态库，可先检查：

```bash
test -f "${ASCEND_HOME_PATH}/opp/vendors/custom_nn/op_api/lib/libcust_opapi.so"
test -d "${ASCEND_HOME_PATH}/opp/vendors/custom_nn/op_api/include/aclnnop"
```

若使用的 vendor 名称或安装位置不是 `custom_nn`，需要同步调整 [`../pybind/CMakeLists.txt`](../pybind/CMakeLists.txt) 中的 include、link 和 RPATH 配置。

## 1. 加载 CANN 环境

请按实际安装位置加载 CANN 环境。例如：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
echo "${ASCEND_HOME_PATH}"
```

不要将某台机器的 `/home/<user>/...` 绝对路径复制到公共文档或脚本中。

## 2. 构建并安装 pybind 模块

从仓库根目录执行：

```bash
cd optimized_transducer/pybind
python3 -m pip install -e . --no-build-isolation
```

安装过程会调用 CMake，并使用当前 Python、PyTorch、torch_npu 和 `ASCEND_HOME_PATH` 定位依赖。依赖版本以 [`../pybind/setup.py`](../pybind/setup.py) 为准。

## 3. 验证模块加载

```bash
python3 -c "import optimized_transducer_ascend_ops as ops; print(ops.__name__)"
```

若导入失败，优先检查：

- `libcust_opapi.so` 是否已安装到 pybind 配置使用的 vendor 目录；
- PyTorch、torch_npu 与 CANN 版本是否匹配；
- CANN runtime 和自定义算子动态库是否位于动态库搜索路径中。

## 4. 运行 Python 样例

以下命令均从 `optimized_transducer/pybind` 目录执行。

仅检查 NPU 调用链：

```bash
python3 only_npu.py
```

同时执行 torchaudio CPU 参考计算：

```bash
python3 test.py
```

两个脚本都需要可用的昇腾 NPU、已安装的自定义算子包，以及匹配的 PyTorch、torch_npu 和 torchaudio 环境。

> 当前脚本包含较大的测试 shape，运行前请先检查设备显存和脚本参数。测试脚本当前主要输出结果，不应仅凭进程正常退出认定精度验证通过。

## 5. ACLNN 示例

ACLNN 调用源码位于 [`../examples/test_aclnn_optimizd_transducer.cpp`](../examples/test_aclnn_optimizd_transducer.cpp)。

本仓库当前未提供该示例的独立构建脚本。请将示例接入实际采用的 CANN 算子工程，并链接已安装的 ACL、ACLNN 和自定义算子库后再运行。

## 验证边界

缺少 Linux、CANN 或 NPU 环境时，应将构建、安装、导入和运行结果记录为 `NOT_RUN`，不能据此声称算子精度或性能验证通过。
